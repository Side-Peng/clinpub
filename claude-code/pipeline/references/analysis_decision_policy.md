# 分析决策规则库（ClinPub 3.0）

> 用途：阶段2 迭代分析循环的**决策依据**。每提出一批新方法前，必须先查本表并记录触发规则。
> 适用：临床研究（RCT / 队列 / 病例对照 / 横断面 / 描述性）

---

## 0. 本文件解决什么问题

2.x 的分析计划是"一次定完"。3.0 是"跑一批、看结果、再决定下一批"。

但"看结果决定下一步"如果没有规则，就只是模型即兴发挥——不可复现、不可审计、换个模型结果就变。

本表把**专业判断**固化成「观察 → 候选动作 → 前置条件 → 不宜做的情形」四元组。规则不规定顺序，只回答：**看到 X 时，值得考虑 Y 吗？**

---

## 1. 三类触发

| 触发源 | 含义 | 示例 |
|---|---|---|
| **R（结果驱动）** | 上一批的结果形态触发的规则 | 组间不显著 → 查功效 |
| **D（数据驱动）** | 数据本身的特征触发的规则 | 缺失率 18% → MICE |
| **U（用户驱动）** | 用户明确要求 | "帮我加个亚组分析" |

每条规则有编号（`R01`/`D01`/`U`），批次记录里必须写下触发的编号。

---

## 2. 结果驱动规则（R）

| 编号 | 观察到的结果 | 候选动作 | 前置条件 | 不宜做 |
|---|---|---|---|---|
| **R01** | 主要终点组间差异不显著 | ① 查统计功效（post-hoc power / 最小可检测效应）② 检查是否被协变量掩盖 ③ 报告非劣效或等效性（若设计允许） | 有明确的主要终点定义；样本量可算 | 不要把"不显著"直接写成"无差异" |
| **R02** | 组间差异显著 | ① 敏感性分析（换检验/换人群/排除极端值）② 协变量调整后复算 ③ 剂量-反应或分层趋势 | 有效应量 + CI | 不要只报 p 就下结论，必须报效应量 |
| **R03** | 相关性显著 | ① 中介分析 ② 调节分析 ③ 非线性关系（RCS） | 有明确的机制假设或先验 | 纯数据挖掘式的中介不要做（无理论支撑的中介=过拟合） |
| **R04** | 时间-事件数据可用 | ① KM 曲线 ② Cox 回归 ③ 比例风险假设检验 | 事件数 ≥ 10×协变量数 | 事件数不足时不要硬上多因素 Cox |
| **R05** | 基线不均衡 | ① PSM ② IPTW ③ 多因素调整后重做主要分析 | 样本量支持匹配（匹配后每组 ≥ 20） | 匹配后不要丢掉未匹配样本的敏感性分析 |
| **R06** | 连续变量与结局呈非线性 | RCS（限制性立方样条） | 样本量足够（每节点 ≥ 10 事件） | 节点数不要超过 5 |
| **R07** | 亚组结果与总体方向相反 | ① 交互作用检验（正式检验，不是分组看 p）② 声明为探索性 | 亚组有先验依据 | 不要把亚组 p 值当成交互作用证据 |
| **R08** | 多个终点均做检验 | FDR / Bonferroni 校正后复报 | 已列出主要 vs 次要终点 | 不要事后挑显著的那个当主要终点 |

## 3. 数据驱动规则（D）

| 编号 | 观察到的数据特征 | 候选动作 | 前置条件 | 不宜做 |
|---|---|---|---|---|
| **D01** | 缺失率 > 10%（关键变量） | 多重插补（MICE）+ 完整病例分析作敏感性 | 缺失机制可假设 MAR | 缺失 > 40% 时插补意义有限，应报局限 |
| **D02** | 缺失有结构性（按设计缺失） | 说明原因，不插补 | 能从数据字典确认 | 不要把结构性缺失当随机缺失处理 |
| **D03** | 结局严重偏态 | 非参数检验 / 变换 / 稳健回归 | 有原始尺度可解释性要求 | 变换后要说明尺度 |
| **D04** | 组间样本量悬殊（> 3:1） | 考虑匹配或加权；报稳健标准误 | — | 不要用等方差假设的检验 |
| **D05** | 存在明显离群值 | 敏感性分析（含/不含离群值） | 能判断是录入错误还是真实极端值 | 不要默认删除离群值 |
| **D06** | 高维变量（变量数接近样本量） | LASSO / 降维 / 预筛 | 有验证策略 | 小样本高维不要做多因素回归 |

## 4. 用户驱动（U）

用户明确要求的方法一律执行，但在批次记录里标注 `trigger: U`，并在 Discussion 的局限性里说明这是用户指定而非数据驱动。

---

## 5. 分叉判断：什么时候停下来问

**默认自动推进**（满足全部条件时）：
- 触发的规则只有一条明确路径
- 该动作不改变已有结论的方向
- 不消耗显著资源（< 2 个方法）

**必须停下来问用户**（任一成立时）：

| 情形 | 为什么 |
|---|---|
| 出现 ≥ 2 条规则指向**互相排斥**的动作 | 例：R01（不显著→查功效） vs R08（换终点做校正） |
| 动作会**推翻已有结论** | 例：主分析改为 PSM 后结论反转 |
| 需要**改变主要终点或主要人群** | 属于研究设计变更，不是分析细节 |
| 动作是**探索性/事后**的 | 必须让用户知道并同意标注 |
| 预算即将耗尽 | 让用户决定是加预算还是收敛 |
| 数据质量不足以支撑该动作 | 例：事件数不足却要做多因素 Cox |

## 6. 退出判据（饱和）

**满足任一即停止迭代**（需记录理由）：

| 编号 | 判据 |
|---|---|
| **S1** | 核心研究假设已被验证或证伪，且效应量 + CI 稳定 |
| **S2** | 连续两批分析未产生新的实质性发现（只重复已有结论） |
| **S3** | 触及分析预算上限（`project_config.yml` 的 `analysis_budget`） |
| **S4** | 用户明确要求停止 |
| **S5** | 数据质量/样本量已成为进一步分析的限制（此时应写入局限性而非继续分析） |

> **S2 是最容易被误用的**：同一结论用不同方法重复三次不算"新发现"。判断标准是"是否改变了我们对研究问题的理解"。

## 7. 批次记录格式（写入 `ANALYSIS_LOG.md`）

每批必须包含以下六段，缺一不可：

```markdown
## Batch {N} — {批次标签}（{日期}）

### 依据
- 触发规则：R01（主要终点不显著 → 查功效）
- 上一批观察：Batch 2 中 {outcome} 组间差异 p = 0.21，效应量 d = 0.18
- 决策来源：自动推进 / 用户确认

### 本批方法
| id | 方法 | 目的 | 状态 |
|---|---|---|---|
| 05_PowerAnalysis | post-hoc 功效分析 | 判断是否效能不足 | ✅ |

### 结果要点
- {method_1}: 效应量 = …，95%CI …，p = …（一句话结论）

### 解读
- 这批结果说明 …（不是复述数字，是判断）

### 下一批决策
- 决定：继续 / 暂停询问 / 停止
- 理由：…
- 若继续，候选：{method list}

### 否决项
- {method_2}: 否决，因为事件数不足（12 事件 vs 需 30）
```

**为什么"否决项"必须记**：它是 Discussion 里局限性段最好的素材，也能防止下一轮又把同样的方法提出来。

---

## 8. 反模式（明确禁止）

| 反模式 | 后果 |
|---|---|
| 无规则依据地"再试试别的" | 数据挖掘，假阳性 |
| 同一结论反复换方法验证 | 伪稳健性 |
| 事后调整主要终点 | 审稿杀手 |
| 只报显著的亚组 | 选择性报告 |
| 迭代到所有 p 都 < 0.05 才停 | p-hacking |
| 不记录否决项 | 下轮重复劳动 + 丢局限性素材 |
| 用 `ANALYSIS_LOG` 代替 `04_Outputs` | 数字必须来自实际产出，不是日志转述 |

## 9. 与方法库的衔接

- 方法的**具体实现**（代码模板、参数、图表规范）查 `analysis_methods.md` 与 `r_patterns.md`
- 方法的**选择依据**查本文件
- 方法的**执行记录**写入 `ANALYSIS_LOG.md`

三者分工不可混：本文件不写代码，`analysis_methods.md` 不管决策。
